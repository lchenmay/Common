# D:\DEV Codex 规则系统使用说明

## 日常使用

1. 从目标 Git 仓库根目录启动 Codex，例如 `D:\DEV\Aiarwa`。
2. 首次启动或 Hook 内容变化后，打开 `/hooks`，核对来源和命令后信任。
3. 正常描述开发任务。Codex 可以读取兄弟仓库，但默认只能修改当前仓库。
4. 发生文件写入后，完成门会要求执行当前仓库的
   `scripts\codex-verify.ps1`。验证失败时不能宣称成功，但允许明确报告真实阻塞，
   不会形成无限续跑。

## 各仓库验证入口

```powershell
D:\DEV\Aiarwa\scripts\codex-verify.ps1
D:\DEV\Common\scripts\codex-verify.ps1
D:\DEV\JCS\scripts\codex-verify.ps1
D:\DEV\TempOfficeKH\scripts\codex-verify.ps1
D:\DEV\yhb-simulation-engine\scripts\codex-verify.ps1
```

使用 `-Json` 输出结构化结果，使用 `-PolicyOnly` 只验证规则基础设施，使用
`-Full` 扩大到仓库声明的完整兼容性范围。

## 受控生成

```powershell
# 先预检，不写文件
D:\DEV\Aiarwa\scripts\regenerate-types.ps1
D:\DEV\JCS\scripts\regenerate-types.ps1
D:\DEV\Aiarwa\scripts\codex-build-device-packages.ps1
D:\DEV\yhb-simulation-engine\scripts\codex-generate-akm-demo.ps1

# 预检通过后才执行
...\regenerate-types.ps1 -Execute
```

包装脚本会拒绝已有生成文件差异、错误仓库路径、缺少权威源变更、陈旧生成器
或未受控的目标。TypeSys 没有默认目标，只支持显式的 JCS 目标 6 和 Aiarwa
目标 20；数据库连接只能通过进程环境变量注入。

## 强制规则

- 永久禁止硬重置、破坏性 `git clean`、强制推送、递归删除和强制结束进程。
- 直接编辑生成文件、直接运行生成器、写入兄弟仓库源码会被 Hook 拒绝。
- 普通推送、SSH/SCP、服务控制和数据库迁移必须经过权限提示。
- `.env`、私钥和证书类文件默认不可读写。
- 审计文件位于 `%TEMP%\codex-policy-audit`，只保存规则名和输入哈希，不保存
  原始命令或凭据。

## 维护规则系统

共享实现位于 `D:\DEV\Common\CodexPolicy`，仓库事实位于各自的
`.codex\policy.json`。修改后运行：

```powershell
D:\DEV\Common\CodexPolicy\Test-AllPolicies.ps1
```

Hook 信任绑定内容哈希，所以修改共享 Hook 或 `hooks.json` 后需要再次通过
`/hooks` 审核。不要为了绕过失败而修改验证脚本、策略模式或临时状态文件；应
修复真实问题，或在最终报告中说明无法通过的检查。

## 当前已知的旧工程边界

- Common 的默认门验证当前 Aiarwa/TypeSys 使用的核心库。`Common-All.sln`
  仍包含需要 Android/MAUI workload 的项目，以及缺少旧 Zmq 类型的
  UtilWebServer。
- JCS 的默认门验证 TypeSys 与 JCS.Shared；修改 JCS.BizLogics 或使用
  `-Full` 时会额外暴露它与当前生成类型的历史漂移。旧 net8 Host 也尚未完成
  向 net10 迁移。

这些旧基线不会被伪装成成功；只是在与当前任务无关时不阻塞核心仓库的正常
开发。任务一旦触及对应模块，验证门会重新把它们作为强制检查。
